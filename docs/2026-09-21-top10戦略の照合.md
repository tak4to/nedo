## 3. A-4 支持閾値スイープ（提出枠で消化）

DOE S3（`tools/doe.py`、se 0.2〜0.3）が測ったのは**厳しくする側だけ**:
`SUPPORT_MIN_COVER` 0.63→0.72 は −1.10（t=3.4）、`SUPPORT_CENTROID_TOL` 0.35→0.45 は +0.07（t=0.4）。
**緩める側は未測定**で、戦略書が「単独で +3.54」と書いているのは重心許容ずれを緩めた側。

`tools/make_variant.py` が `agents/submit` から**定数1行だけ**違う zip を生成する（`agents/variants/*.zip` + 変更行を記録した `.json`）。

| zip | 変更 | 1変数 |
| --- | --- | --- |
| `support_centroid_tol_045` | `SUPPORT_CENTROID_TOL` 0.35 → 0.45 | ✔ |
| `support_centroid_tol_055` | 0.35 → 0.55 | ✔ |
| `support_centroid_tol_07` | 0.35 → 0.70 | ✔ |
| `support_min_cover_055` | `SUPPORT_MIN_COVER` 0.62978 → 0.55 | ✔ |
| `support_min_cover_05` | 0.62978 → 0.50 | ✔ |

- 生成物と `agents/submit` の差分が意図した1行だけであることを `diff -r` で確認済み
- **提出順の推奨**: `centroid_tol_055` → 結果を見て 045 か 07 へ（片側に崖がある可能性があるため、いきなり極端側に行かない）。基準は現行 LB **56.766**
- 判定の注意: ローカルの探索シード雑音は sd 5.95/シーン。**LB の再現ノイズ（同一zipの再提出差）は未測定**なので、小さな差は採用の根拠にしない。採否は「主枠は保険なしに差し替えない」（戦略書 §6）に従い2枠目で確認してから
- `SUPPORT_MIN_COVER` を変えると救済ラダー Lv2（`MIN_COVER × 0.5`）も連動して動く点に注意

### 提出結果（1変数ずつ、基準は現行 LB 56.766）

| 日付 | zip | 変更 | LB | 差 |
| --- | --- | --- | --- | --- |
| 09-21 | `support_centroid_tol_055` | `SUPPORT_CENTROID_TOL` 0.35→0.55 | **56.0546** | **−0.71** |

緩める側の最初の点は負。DOE S3 の 0.35→0.45（+0.07, t=0.4）とは矛盾せず、「0.45 付近は中立、0.55 までで悪化に転じる」とも「雑音」とも読める。
**同一 zip の再提出差が未測定**のため、この1点だけでは区別できない。

**方針（2026-09-22、ユーザー決定）: 本番スコアを使った検証提出は行わない。** A-4 の残り4本（`centroid_tol_045`/`07`、`min_cover_055`/`05`）は**提出しない**。
`centroid_tol_055` の −0.71 は事実として記録するだけで、機序の解釈や再提出による雑音の測定はしない。主枠は現行 `agents/submit.zip`（56.766）。
`agents/variants/` と `make_variant.py` は残置するが、提出には使わない。

## 4. 凍結前点検 `tools/preflight.py`

提出 zip をクリーンな一時ディレクトリへ展開し、**本物の `EvaluationApp`（spawn した worker、`RLIMIT_AS`=max_mem、評価基盤と同じタイムアウト）**で完走させる。
`--cpus 4 --load 2` で 4 CPU に固定し負荷プロセスを競合させ、評価基盤（4vCPU）相当の遅さを再現する。

静的: zip 構造 / 作業ツリーとの同期 / 評価基盤イメージに無い import / 無防備な第三者 import
動的: 全タスク完走 / タイムアウト 0 件 / 最悪呼び出し時間の対制限比 / 子プロセス peak RSS

**`agents/submit.zip` の結果（4CPU固定 + 負荷2、サンプル config 2タスク）: PASS、警告 0**

| 項目 | 実測 | 制限 |
| --- | --- | --- |
| zip と作業ツリー | 4ファイル全て一致 | — |
| task 000（optimize あり） | fill 44.10 / 積載率 0.805 | — |
| task 001（棚あり・k=10） | fill 30.32 / 積載率 0.643（WORKLOG の値と一致） | — |
| optimize 最悪 | **149.95 s（83%）** | 180 s |
| policy 最悪 | **5.09 s（51%）** | 8〜10 s |
| タイムアウト | 0 | — |
| peak RSS | 81 MB | 12 GB |

コード上の依存は numpy（agent.py 先頭）と pybullet（`twin.py` 内で遅延 import、`USE_SETTLE_TWIN=False` で未使用）のみ。
環境変数・ファイル・ネットワーク・sleep への参照は agents/submit に無い（§10-1 の「出力フィールドへの符号化」に当たるものは無い）。

**`submit_safe.zip` は作業ツリーと別スナップショット**（総括 §4b #2 の通り設計ごと古く、LB 未測定）。凍結までに最終2枠の片方をこれにするかを決める必要がある。

```bash
.venv/bin/python tools/preflight.py --zip <zip> --cpus 4 --load 2        # 約3.5分
.venv/bin/python tools/preflight.py --zip <zip> --static-only            # 即時
.venv/bin/python tools/make_variant.py --list-sweep                      # A-4 の5本
```

10/15 の凍結後は、最終2枠の zip それぞれにこの点検を通すこと。
