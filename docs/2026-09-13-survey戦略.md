## 0. 結論

**survey の骨子は採用する。** 「stability の機序を先に観る」「パラメータを振るより構造を変える」
「評価ノイズと評価シーンを先に直す」は、このプロジェクトの実績（機序調査で勝ち、
単独パラメータ A/B は0勝23敗、要因計画でパラメータ空間は枯れた）と一致する。

**ただし survey の前提のうち5点は実装・実測と食い違う。** 修正して取り込む（§1）。
特に「支持ポリゴン（提案B）」「搬入経路の事前判定（提案E）」は**既に実装済み**で、
「インターロック（提案C）」は**CEM が逆（柱積み）を選んだ事実**と衝突する。

**手元データで機序の予備観察をした結果、stability の主因は個別の転倒ではなく荷全体の滑り**
（置いた荷物の 61〜68% が揺動で 5cm 以上動く）で、**stability と cog は逆方向に引き合う**。
両方に同時に効くのは**密度**だけである（§2）。

**残りは36日**（スクリーニング終了 10/19、必要書類 10/26）。survey の8週間計画を5週間に圧縮する（§4）。

## 2. 機序の予備観察（survey 提案A の第一段、既存データで実施）

現行エージェントの結果 JSON（オフライン=要因計画の出荷構成 64、オンライン=V14 の 96。
policy は CEM 以降変えていないのでそのまま使える）から集計した。**ローカル代理の stability** である点に注意。

### 死因

| セット | nothing-fits | topple |
| --- | --- | --- |
| オフライン（k=1） | 97% | 3% |
| オンライン k≥5 | 94% | 6% |
| オンライン ktest | 84% | 16% |
| オンライン棚 | 88% | 12% |

### stability の相関（160シーンをプール）

| 量 | 相関 | 偏相関 |
| --- | --- | --- |
| 積載個数 `pct` | **−0.04** | — |
| 相対重心高 | +0.37 | **+0.43**（fill を制御） |
| 充填率 `fill` | +0.19 | **+0.30**（重心を制御） |
| 最上面の上の空き | −0.02 | +0.07（fill を制御） |
| `cog_score` | **−0.29〜−0.54**（セット別） | — |

| 重心三分位 | 相対重心 | stability | fill |
| --- | --- | --- | --- |
| 低 | 0.46 | 24.1 | 38.0 |
| 中 | 0.49 | 28.3 | 41.4 |
| 高 | 0.53 | 30.9 | 35.0 |

**置いた荷物のうち揺動で 5cm 以上動く割合: 61〜68%。**

### 読み取れること

1. **stability は積載個数の税ではない**（r≈0）。積むことと安定させることは両立する
2. **主因は個別転倒ではなく荷全体の滑り**。3分の2の荷物が動いている。個別荷物の転倒を防ぐ
   支持ポリゴン（提案B）は的外れの可能性が高く、**横方向の拘束**（壁・隣接荷物・隙間の少なさ、
   survey 1(c) / EUMOS の思想）が本命になる
3. **重心が高いほど安定**だが、**最上面の上の空きとは無関係** → 「蓋に届いて押さえられている」
   ではない（ただし上の空きは 160 中 150 が 5〜15cm に集中しており、この否定は弱い）
4. **stability と cog は逆方向に引き合う**。重心を上げて stability を取れば cog を払う。
   CEM がやったのは恐らくこれで、`W_CEIL=+469`（全荷物の上の隙間を嫌う＝上へ押し上げる）と
   cog 63.7 → 51.6 が整合する。重みが非公開なので、この取引の損得は LB でしか判定できない
5. **両方に同時に効くのは密度だけ**。fill↑で stability↑、かつ fill↑で重心↓（r=−0.23）

**すべてシーン間の相関であり因果ではない。** シーン内の介入で確かめる（P2）。

## 3. 施策（優先順）

### P0【初日・工数ほぼゼロ】最新提出のフィードバック5指標を記録する

実 LB の `stability_score` が、ローカル代理（約25〜28）と桁で合っているかを見る。
公式定義は3成分なので乖離はあり得る。**以降の全 stability 施策の期待値がこれで決まる。**

- 実 LB stability が既に高い（例: 60超）→ stability 路線を縮小し、密度・cog 側へ
- ローカルと同程度に低い → 本戦略どおり

### P1【〜3日】ローカル stability 代理を公式定義に寄せ、機序ロガーを作る

1. `tools/scores.py` の揺動テストに、公式が挙げる残り2成分を追加する
   - 揺らした間の手荷物への力: `getContactPoints` の法線力の最大値・積分
   - 運動エネルギー: `getBaseVelocity` から荷物ごとの KE の時間積分
   - 評価基盤は「目標の 8cm 上から落とす」ので、整定もそれに合わせる
2. 荷物ごとに「揺動でのずれ・高さ・床接地か・壁接触数・隣接荷物との側面接触面積・上の空き・質量」を記録するロガー
3. 3成分のどの組み合わせが P0 の実 LB 値と桁が合うかを見る（較正点は少ないので強い較正はしない）

**なぜ最初か**: survey 自身の Caveat（代理は本番と一致の保証なし）と、今回の物理判定器の失敗
（「1配置が崩れるか」の二値判定用に較正した計器を、エピソード全体の順位付けに流用して落ちた）
の教訓。**計器を用途に合わせて検証してから、その計器で最適化する。**

### P2【実施済み・確定】機序観察

`tools/mechanism_log.py`（荷物ごとに床接地・壁接触数・隣接側面接触面積・上の空き・
高さ順位・力・エネルギー・変位を記録）を作り、20シーン 801個の荷物で集計した。

| 観察軸 | 結果 |
| --- | --- |
| **床接地** | **床接地は 0.009m / 2% しか動かない。非接地は 0.164m / 82%。** |
| **隣接荷物との側面接触** | **孤立（接触なし）は 0.165m / 78%。接触ありは 0.104m / 56%。** |
| **コンテナ壁との接触数** | 0〜2枚でほぼ横ばい（0.132〜0.142m）。**効いていない** |
| **コンテナ内の高さ** | 低 0.085m/46% → 中 0.156m/81% → 高 0.175m/79%。単調に悪化 |
| **天井までの空き** | 5cm未満 0.220m/88% と最悪。15cm以上 0.130m/66% |

**判定**:
1. **床層が滑る → 否定。** 床は最も安定している
2. **孤立荷物が動く → 強く支持。** 唯一 disp を 1.6倍動かした軸
3. **上層が不拘束 → 支持。** 高さと天井空きの両方が単調
4. **個別の転倒（壁で説明） → 否定。** 壁接触数はほぼ無相関

**結論: 主因は「非接地層全体が横方向の支持を失うこと」で、支えているのは
コンテナの壁ではなく隣接する荷物同士。** survey 1(c) は半分正しかった
（壁ではなく隣接支持の方）。survey B（個別の支持ポリゴン）は的外れと確定した。

**方向性を1つ覆す**: §2 のシーン間相関では「重心が高いほど stability が良い」
という逆説的な相関が出ていたが、それは交絡だったとみてよい
（重心の高いシーン＝側面接触の多い密な配置になっていた可能性）。
**効くのは重心の高さそのものではなく、側面拘束の有無。** P3 の特徴量選定はこちらを主軸にする。

### P3【1〜3週目】観察で選ばれた特徴量を「重み0で追加」→ 凍結 → 同時最適化

**survey の「1施策 = 1変更で A/B」は採らない。** このプロジェクトで0勝23敗の型であり、
分散成分分解（`tools/varcomp.py`）で1本の A/B は se 0.7〜1.0 でしか測れないと確定している。
CEM 14 次元の同時最適化が本プロジェクト最大の改善だった型に揃える。

**候補特徴量**（P2 の確定結果で優先順位を付け直した。すべて重み0 = 無効で出荷し、最適化に判定させる）:

| 特徴量 | 優先度 | 出典 | 現行との違い |
| --- | --- | --- | --- |
| **側面の隣接接触面積**（コンテナ壁ではなく荷物間） | **最優先** | P2 実測（唯一 disp を1.6倍動かした軸） | 現行 `W_WALL` はコンテナ壁の数のみ。荷物同士の側面接触は候補生成でもスコアでも見ていない |
| **最上層限定の天井ギャップ** | **高** | P2 実測（天井5cm未満で最悪）＋ survey F | 現行 `W_CEIL` は全荷物に掛かり、非表層の重心を押し上げてしまっている |
| 継ぎ目ずらし（連続値） | 中 | survey C、パレタイジング実務 | 現行 `W_SEAM` は「どれか1辺が揃えば1」の二値で、CEM は柱積み側を選んだ。連続量として別に入れ、両立を最適化に判定させる |
| 支持余裕の連続値 | 低（P2 で個別転倒は否定的） | survey B の未実装部分 | 現行は合否のフィルタのみ |
| 配置後の表面粗さ増分 | 中 | survey D、O4M-SP の height difference | 現行 `W_WASTE` は**足元の空洞**で、表面の平坦性とは別の量（Wang & Hauser 型の waste は −0.78〜−2.76 で却下済み、空きはスカイラインの上にあるため） |
| 棚下ゲート（ハード小型のみ） | 中 | survey G | 要因計画で `USE_UNDER_OVERHANG` は +0.42 (t=1.48) と、無条件追加の −2.68 から符号が反転した領域にある。soft 減点の原因を直接断つ |

**実装済み**: `tools/packer.py` に `W_SIDE`（重み0で出荷、`_side_contact_frac` で候補生成に配線）を追加。
構造的に no-op であること（`bool(0.0)` のガードで分岐自体が実行されない）を確認済みで、
非ゼロに設定すると5シーン全てで挙動が変わることも確認済み（`ab.py --set p:W_SIDE=500`）。
`tools/cem.py` に `full15`（`full14` の CEM 結果を初期値とし `W_SIDE` を第15次元として追加）を登録済み。
15次元でのドライラン（4シーン×4個体×1世代）が正常終了することを確認済み。

**最適化の設計**（survey I を実測で修正）:

1. **エージェントを凍結してから回す**（survey I-4。今回実際に踏んだ）
2. **訓練シーンを実 config の結合に合わせて再構成**: 課題A = `optimize=True × k=1`（`scenes_off.json`
   + `scenes_offtest.json`。旧訓練プールは実オフライン条件が 64 中 1）
3. **1個体あたり複数シード**。`Var(b)=0` なのでシーンとシードは交換可能。se は総ラン数で決まる
4. **上位個体のレーシング**（irace 型）: 世代の上位だけ追加シードで再評価してから選ぶ。
   前回は第7世代の 1位と2位の差が 0.06 で、出荷個体は実質偶然に選ばれていた
5. 探索器は CMA-ES（`cmaes`、ノイズ下で `cm<1`）でよいが、**効くのは 3・4 の評価設計の方**
6. 目的関数は P1 の公式定義準拠の代理（`stability_score` が力・エネルギーを含むようになった
   `tools/scores.py`）を含む `smooth_objective`

**実行コマンド**（本番、夜間バッチ・`nohup`・`--resume` 対応）:
```bash
../.venv/bin/python cem.py --scenes scenes_off.json,scenes_offtest.json \
    --params full15 --pop 20 --gens 8 --jobs 14 \
    --optimize-budget 60 --out cem_full15.json --resume
```

コスト: 前回 CEM full14 は 10,240 エピソード ≈ 11.5 時間。full15 も次元1つ増えただけなので同程度。

**合否**: 未使用プール（多シード）と実タスク（多シード、`OFFLINE_SEED_SALT` を振って）の両方で
composite +1.0 を超えること。se 0.37 の設計なら +1.0 は検出できる。

### P4【2〜4週目・並行】詰まり（nothing-fits 84〜97%）の診断

survey 提案E を「事前判定の追加」ではなく**候補の取りこぼし診断**として実施する。
死亡時点の状態に 3cm 総当たりをかけ、「オラクルを通り、支持判定も通る配置」が残っているかを見る。
道具は既にある: `tools/diag_gap.py`（「詰まった状態で、総当たりが見つける配置を packer 自身の探索も
見つけるか」）。前回これを使ったのは `MIN_CALL_BUDGET` 修正前（09-01）なので、現行エージェントで取り直す。

| 結果 | 次の手 |
| --- | --- |
| 残っている | 候補生成の網羅性が律速 → survey E（EMS 型の候補追加。制限ではなく**追加**の形で） |
| 残っていない | 本当に満杯か到達不能 → survey D（表面平坦化で「置ける面を作る」）を P3 の特徴量で |

**期待値の注意**: 09-06 の LB 較正では積載率を +26.5pt 上げても LB は +1.72 しか動いていない。
詰まり解消の優先度は、P0 の実 LB 内訳と、積載率の閾値近傍にいるシーンの比率で決める。

### P5【4〜5週目】再最適化と提出

P3 の特徴量セットで最終の同時最適化 → 凍結 → 提出2枠を決める。
暫定評価と最終評価でシーンが入れ替わるので、**暫定 LB への合わせ込みはしない**。
2枠は「分布平均の重み（頑健）」と「レーシング勝者の重み（攻め）」に分ける。

## 5. 判断を変える閾値（実測版）
